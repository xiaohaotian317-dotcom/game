# 项目需求

最后更新：2026-10-29（Asia/Shanghai）  
项目：秘境决斗  
依据：本会话中可见的完整用户沟通、已保存的概念设定和当前源代码。未提供的早期方案具体内容不补造。

## 1. 项目目标与当前阶段

制作一款双人联机、同地图直接对抗、能在较短时间决出胜负的游戏。最初考虑过双坦克，但用户明确不局限于坦克；后续选择了有跳跃、下落、技能衍生和场景互动的暗色奇幻 2D 横版平台对战方向。

核心体验是移动与落点博弈、技能时机、出其不意的操作和真实地图反馈。地图应给双方追击、撤退、绕行和躲避空间。具体单局时长、胜负规则及联机方案尚未最终确定，不能将概念图中的 01:12 当作已确认比赛时长。

当前交付为六职业单人动作/战斗/机关试炼。六位可切换，三个地图可操作，含训练木桩、反击设置和放大动作检视。双人网络对战、正式大厅、抽卡与闯关尚未实现。

## 3. 人物与连贯动作

- 外观、服装、武器、动作、特效应对应职业，不能六个人只换配色或重复同一挥手姿势。
- 每位需要可连续衔接的待机、移动、起跳、下落、落地、普攻、Q/E/R、受击、倒地等状态；施法有起手、蓄力、释放、命中反馈与收招。
- 动作要丝滑，技能特效要与释放时机和身体发力衔接，不能忽然跳帧、瞬移肢体或在收招时断开效果。
- 头颈身体必须连接正确；肩、肘、手、武器要有稳定锚点。转向、跑跳、抬臂和连续 R 都要检查。
- 上臂末端固定在肩膀，允许小幅自然错位，不允许大幅乱飞；避免抬胳膊有不明部件向后甩。
- 站姿重心自然，避免不协调后仰。保留职业需要的合理前倾。
- 原两位施法左手只需自然露出并保持静止，不增加托举、挥动或掌心施法动作；身体自身呼吸和重心变化可自然带动它。
- 用户允许漂亮的女角色，但必须符合职业设定。森灵女性方向已确定。
- 放大检视页与游戏使用同一套实际角色绘制，能播放、定格、拖动动作进度及查看左右朝向。

## 4. 战斗、特效与落点硬性规则

1. 火要像火：火芯、焰尾、燃烧与灼烧可辨；陨石要有岩体、熔岩裂纹、下坠速度和重量感，不能只是小光球。
2. 爆炸和大招需要可感知的威力：合理节奏、冲击圈、碎屑、受击、短暂停顿与音效配合，同时保证角色和危险范围可读。
3. 木灵鹿应像鹿，有明确身形和独立血条；自动找敌人、回头、追击、跨台越障和攻击，不能只一直向前；保留二段指令的玩家控制。
4. 用户要求普攻“再慢百分之 50”。本轮已按普攻间隔增加 50% 落实，未降低弹体飞行速度；若以后调整，明确说明频率和间隔的区别，不悄悄改回高速连发。
5. **普通攻击不能穿透实际墙体、石台与实体掩体**；近战普攻也不能隔墙命中。远景装饰不是实体墙，不能将整张背景当碰撞层。
6. **技能可以穿过障碍或上层平台**，按职业设计执行；不能把普攻挡墙规则套在所有技能上。火陨石不能被最上层屋顶提前截住。
7. 陨石从被接受的点击到落地约 **1 秒**（正常速度）。不能点击后慢慢飘落，让目标轻易走开。
8. 火陨石、爆燃印、森灵古树等指定台面技能，从鼠标位置竖直向下取第一块有效、可站立台面，保持点击横坐标；不是选距离最近的台面。
9. 点在第二层和第三层之间，就作用于第二层；点在第一层和第二层之间，就作用于第一层。缺口或坏桥继续向下找实际支撑。
10. 古树必须从鼠标下方台面长出，不能长在空中。移动支撑要跟随，支撑消失时合理消散；相同原则用于需要地面的持续领域。霜语者主动造冰台属于明确的职业造路能力。
11. 二段通过限时内再次按同一键触发，图标与倒计时清晰；每次一段至多开放一次二段，共用冷却。返影不重置生命和技能冷却，不可用返程无限刷资源。

## 5. 场景、地图空间与交互

沿用已提供、已确认的详细手绘场景，保留城堡遗迹、拱门、旗帜、藤蔓、繁花、瀑布和场景层次。最新要求是“之前的背景稍微减淡一点”，不能再退回用户已否定的空旷简化场景，也不能仅通过降低透明度处理。

背景的对比、亮暗、饱和度、锐利纹理应克制，人物和技能是视觉主体；不能一眼只看到场景而找不到角色。保留原细节与适度收敛视觉强度同时成立。当前轻调色为实现方案，不是用户锁死的三个系数。

| 地图 | 必需机关与反馈 |
| --- | --- |
| 月光遗迹 · 断桥与月镜 | 木桥受击破坏并移除支撑；月台可升降并承载角色；月镜转向折射投射物 |
| 熔岩祭坛 · 导流与摆锤 | 地火先预警后喷发；阀门改变喷发/安全通道；摆锤受击摆动并影响落点 |
| 浮空花园 · 风道与藤桥 | 风铃改变气流方向；藤桥生长后可站立、结束后移除；弹跳花踩压蓄力后上弹 |

- 地图必须够大，有跑动和躲避空间；当前已从 1440 扩至 2304 宽，增加左右回廊、掩体及镜头跟随/全景。
- 必要台面和路线必须能以基础移动与二段跳到达，不能出现二段跳也上不去的关键平台。
- 平台贴图、碰撞边缘、机关承载面与真实落脚点对齐；不能只有好看的概念图而没有可交互反馈。

## 6. 正式界面与模式需求

目标流程：启动总界面 → 点击开始 → 游戏主大厅 → 英雄召唤池 / 双人决斗 / 单机闯关。

大厅需有各模式入口；召唤池、角色图鉴、玩家资料、金币和设置已有概念方向，正式数据和进度规则待实现。现有金币、抽卡费用等概念图数字不代表已经实现经济系统。不得把当前“启动页直接进入试炼”误记为已完成正式大厅。

战斗 UI 应清楚呈现头像、生命、计时、技能、冷却、二段窗口、召唤物生命与相关被动资源，不能靠大量说明文字代替真实状态。双人正式战斗 HUD 还需绑定两名真实玩家。
