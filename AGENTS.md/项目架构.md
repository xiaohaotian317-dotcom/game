## 1. 工作区、源码与入口

| 位置 | 职责 / 注意 |
| --- | --- |
| 根`AGENTS.override.md`、代码内`AGENTS.md` | Codex入口；每次依次完整读根`AGENTS.md/`内三文档；入口不复制项目状态 |
| 根`AGENTS.md/` | 用户指定的三份集中记忆，不改成同名普通文件，不建立第二套权威副本 |
| 根`.git` | 用户GitHub仓库，origin为`https://github.com/xiaohaotian317-dotcom/game.git`，main；此处提交真实代码/美术/文档 |
| `arcane-duel-lab/` | 游戏项目；其中旧嵌套`.git`属原Sites历史，不在此提交代替根仓库，不变成空子模块 |
| `arcane-duel-lab/dist/` | **实际手写源码与原始运行美术**，不是可随意删除的构建缓存 |
| `美术概念/` | 完整概念原图、画册、提示词、取舍与哈希记录；概念不自动等于运行资产 |
| `发行/` | 版本化Windows目录/ZIP；不提交庞大成品包，不覆盖旧包 |
| 代码`tests/`、`scripts/`、`validation/` | 自动检查、审计/打包工具、报告和QA截图；QA夹具不打入成品 |

`dist/client/`、`dist/server/`、`network-host/public/`、`.build`等是生成副本；`.local-data/`为本地数据库。源码与生成物不能混淆，不把凭据/SQLite/浏览器存档/缓存上传。

协作执行：主Agent统一开发/接入；素材子Agent按任务仅写`美术概念/协作交付/<任务ID>/<Agent名>/`，目录随实际任务建立。它是待审素材交付区，不是运行时资源或第四份项目记忆；正式资产/meta/引用由主Agent检查后接入。Agent上下文独立但工作区共享，写入归属、监督与验收规则集中见第三份文档“主Agent统筹的并行协作”。

页面：`dist/index.html`启动/训练；`lobby.html`大厅/英雄图鉴；`summon.html?hero=<ID>`独立英雄卡池；`characters.html`动作检视；`skills.html`技能图鉴；`duel.html`房间/对局；`campaign.html`世界图/选队/单机关卡；`bestiary.html`妖兽图鉴；`enemies.html`交互试炼；`desktop.html`离线/LAN连接。服务支持`/lobby`、`/duel`、`/summon`等无后缀别名。

技术：原生ES Modules + HTML/CSS + Canvas2D战场 + DOM交互UI + WebAudio；Node服务/SQLite，Sites用Worker/D1，Windows用Electron。根项目要求Node≥22.13；独立部署示例Node24；桌面当前Electron45.2.1、@electron/packager20.3.0。

- 背景低对比缓存仅背景层，战斗角色/实体/技能/HUD独立清楚。当前PvP远景默认`saturate(.76) contrast(.84) brightness(.98)`、alpha0.9；单机关卡缓存默认`.73/.82/.92`、DPR上限1.5，避免每帧滤整张大图。
